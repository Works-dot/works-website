# Nine legacy blog posts: HU translation rollout

The nine specifically reviewed HU translations were published on production through the existing Strapi admin content-manager API. No CMS environment switch, general migration flag, database operation, deploy API, or GitHub push is needed for these content writes. Do **not** set `STRAPI_TRANSLATE_LEGACY_BLOG_HU` or `STRAPI_RUN_CONTENT_MIGRATIONS`; the guarded startup migration remains disabled and its original checks remain in place.

The targeted release command is `node artifacts/strapi/scripts/publish-legacy-blog-hu.mjs prepare`, followed by `apply <printed-journal-path>` and `verify <same-journal-path>`. The credentials must already be available to the process as `STRAPI_ADMIN_EMAIL` and `STRAPI_ADMIN_PASSWORD`; the admin token stays in memory. `prepare` checks all nine source fingerprints, draft/published HU parity, EN documents, identities, locale links, component structures and media **before any CMS write**. It saves all 36 full admin snapshots (HU/EN draft/published, including populated media) in a mode-0600 ignored backup and creates a mode-0600 resumable journal in `.local/backups/`. An interruption must be resumed with the **same** journal, not a new preparation. Each write rechecks the remaining baseline, updates only HU title/excerpt and existing content-block text/captions, retains component IDs and media references, publishes just that HU locale, then checks the result; a discrepancy aborts without reporting success. A non-atomic interruption can leave some posts published: inspect the journal and resume `apply` before claiming a complete release. Never resolve a concurrency conflict by overwriting editorial changes.

Production backup: `.local/backups/legacy-blog-hu-1790692017617.json`; journal: `.local/backups/legacy-blog-hu-1790692017617.journal.json`. All nine journal entries are complete. `verify` confirmed all nine public HU translations and their original hero/body media, and the unchanged public EN copy/media and admin EN draft/published documents. The focused script, original migration guard test and translation package test passed.

Keep the deployment order and gates: **CMS service first**, confirm the CMS and media are healthy, **website service second** (its production build fetches fresh published CMS data and refuses missing HU translations). Never deploy the website against stale/unverified CMS content. The checked-in website cache is not a substitute for production verification. Website deployment and live HTML verification are separate from this CMS publication; a successful admin publication does not claim they happened. No manual flag-setting/removal step is required of the user.
